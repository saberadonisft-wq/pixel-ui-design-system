## 1. Decision order

1. Obey the family explicitly named by the user.
2. Extract reference evidence: silhouette, frame depth, icon scale, type scale, texture, density, material, and light.
3. Count strong family signals; do not choose from theme nouns alone.
4. Check product task and information density.
5. Choose one primary family; record secondary influence as a constraint.
6. If references show large decorative modules with illuminated frames, choose Ornamental.

Never default to Tactical Pixel HUD. Dark color, data, cyber semantics, inventory, or fantasy lore do not select a family by themselves.

## 2. Ornamental Pixel Game UI

Choose for large authored interface assets, multi-layer material frames, bright hard-lit ramps, corner hardware, bolts/brackets/plates, reinforcement stripes, dominant per-module accents, large icons, and large readable pixel typography.

- Modern responsive page using a few large modules.
- Four purposeful layers: silhouette, structural material, illuminated accent, calm dark center.
- One dominant five-shade semantic ramp per module.
- Detail Level 1 for hero/account/action; Level 2 navigation; Level 3 controls; Level 4 content.
- Icons occupy 15–25% of module width.
- Use a tested Vietnamese display fallback and tabular values.
- Mobile stacks and removes secondary hardware without losing silhouette.

Read [ornamental-pixel-game-ui.md](ornamental-pixel-game-ui.md) and [nine-slice-system.md](nine-slice-system.md).

## 3. Minimal 8-bit UI

Choose only for explicit early-console, tiny logical canvas, severe palette limit, or primitive controls. Use 2–4 colors, simple one-band depth, and 8/16px sprites. Never use it as an easy fallback for a detailed reference.

## 4. 16-bit RPG UI

Choose for classic console RPG composition with inventories, quests, party stats, dialogue, and medium-detail illustrated material frames. Use 16/24/32px sprites and one-to-three frame layers. Fantasy semantics alone do not select it.

## 5. Cozy Pixel UI

Choose for warm playful atmosphere, character-led scenery, generous spacing, and low information density. Use fewer borders, calm surfaces, and expressive 32/48/64px sprites. Never use against high-detail metallic references.

## 6. Tactical Pixel HUD

Choose only for explicit cockpit, combat telemetry, monitoring, tactical instrumentation, or dense keyed data. Compact rails, repeated keyed rows, status patterns, and segmented meters are valid. Do not use for premium ornamental navigation because the page is dark.

## 7. Cyber Pixel Interface

Choose for terminal, network, old-computer, command workflow, cyberpunk hardware, or electronic console metaphor. Keyboard-led composition and controlled scan/grid texture are valid. Neon glass and smooth gradients are not pixel identity.

## 8. Pixel Data Dashboard

Choose for charts, tables, analytics, simulators, and modern task flows where data readability is primary. Use one detailed outer frame and calm data interiors, quantized marks, tabular figures, and accessible alternatives.

## 9. Conflict and failure checks

References and explicit user language outrank defaults. Fail when Ornamental becomes Cozy because content is fantasy, dark becomes Tactical without instrument density, data becomes SaaS cards with pixel type, Minimal is selected because it is easier, or every family is the same rectangle with different colors.
